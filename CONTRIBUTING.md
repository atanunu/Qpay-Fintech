# Contributing
Read [AGENTS](AGENTS.md) and the [mandatory documentation policy](devdocs/project/13-DOCUMENTATION-STANDARD.md).

A feature delivery includes code, schema/config implications, relevant tests actually executed, API/workflow docs, canonical service README status, refreshed root summary and real changed-screen evidence. Keep limitations and skipped tests visible. Use the issue/PR/evidence templates and preserve stable IDs.

Source implementation, verification, provider acceptance and production release are separate assertions. Link exact source/test paths and commit evidence. A mock, UI placeholder or provider adapter is not the finished integration. Decompose broad epics before treating them as sprint tasks.

Prefer coherent reviewed PRs. Do not overwrite concurrent commits or use force push. Verify remote status and checks. The committed documentation workflow checks pushes and pull requests. A repository administrator must separately configure required status checks and review rules; see `devdocs/project/21-REPOSITORY-SETTINGS.md`. Workflow presence does not prove that branch protection is active.

Use only synthetic screenshots with provenance. Maintain independent staff/customer auth. No secret, raw identity document, real payment record or production account changes for docs. Security issues should use the private route established by the repository owner, not a public issue containing sensitive evidence.
