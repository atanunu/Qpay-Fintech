# Notification contracts, delivery and accounting boundaries
Status: documented interface design plus a tested content contract/factory. Go storage, endpoints and live delivery adapters are not implemented by this package.

## Atomic outbox design
Persist an immutable notification intent in the same PostgreSQL transaction as its business event. Suggested fields: notification_id, event_id/type/version, aggregate_type/id/version, workflow_id/version, template_release_hash, recipient_ref, contact_snapshot_id/version, purpose/category, locale, eligibility_policy_version, occurred_at, expires_at, dispatch_state, attempts, next_attempt_at and correlation_id. Sensitive challenge material needs an approved encrypted ephemeral store/redaction strategy; never put long-lived passwords, PINs, PAN/CVV, BVN/NIN, documents or provider secrets in this table or Novu payloads.

Enforce uniqueness on the event/recipient/channel/occurrence/version tuple. Receipt copies and reminders have new explicit occurrence/request IDs without creating new financial operations. Use row leasing/locking, bounded workers, atomic claims and recoverable leases. Persist the external transaction/message references and dispatch fingerprint. Uniqueness and idempotency retention must cover the replay window, not just the visible email TTL.

Dispatch sequence: verify unexpired/current event; resolve authorised recipient snapshot; recheck contact status, preferences and suppression; create/update the scoped Novu subscriber safely; trigger the stable workflow using the pinned API contract; persist the result or ambiguity. A timeout after submission is ambiguous. Query/reconcile the same notification operation using the available target API/provider evidence before any controlled retry. Do not claim network-wide exactly-once delivery. Pin and test Novu trigger deduplication behaviour and retention rather than assuming transactionId is indefinitely idempotent.

## Built-in payload contract
Per-workflow JSON schemas and fixtures are generated by [content.mjs](../../Novu/src/content.mjs). Required common fields: version=1, event_id, notification_id, recipient_ref, reference, audience, state, locale=en-NG, name, occurred_at and expires_at. Only amount-bearing rows accept amount_minor/currency; only the three challenge rows accept code; only optional/marketing rows accept unsubscribe_ref. additionalProperties is false. UTC timestamps include milliseconds and Z. Domain event storage may contain additional fields but must project a minimal notification payload rather than forwarding the complete financial record.

The supplied state string must equal the catalogue guard, but this is structural validation only. The live authorise binding must load the trusted business/recipient/consent state and validate the guard, current aggregate version, authorised contact snapshot, destination eligibility, product activation and current release. Client-supplied audience/state values confer no authority. APIbackend authenticates the private bridge policy call, scopes it to the notification ID and avoids arbitrary PII lookups.

The factory [workflows.mjs](../../Novu/bridge/workflows.mjs) accepts the official workflow function, an explicit release allowlist, approved scopes, brand, providerOptions, authorise and recordSuppression bindings. It registers an email step with a pre-send skip guard. Policy unavailability fails closed; a denied/stale notification is suppressed and recorded. Actual SDK discovery, skip behaviour, replay and policy-race handling require live integration tests. No permissive default policy or mock policy may be used in the deployed bridge.

## Independent delivery states
| State | Meaning and allowed next action |
|---|---|
| planned/queued | Durable intent exists, no send claim |
| claimed | Worker lease held; expired lease can be recovered |
| submitted | Novu accepted trigger; not proof of mailbox delivery |
| submission_unknown | Transport result ambiguous; investigate original operation |
| provider_accepted | Delivery provider accepted message; preserve provider ID |
| delivered | Verified provider evidence that recipient server accepted delivery; not proof a human read it |
| delayed | Still unresolved; bounded status review within expiry policy |
| rejected/bounced/complaint | Record provider evidence and appropriate suppression; never alter financial outcome |
| suppressed/expired | Intentionally not sent; reason and policy version retained |
| dead_letter | Unsafe or exhausted processing requires controlled investigation |

Retain immutable event observations. Handle duplicate and out-of-order callbacks without erasing later evidence; a complaint after delivery remains important. Opens/clicks are not authentication, legal consent, human-read proof or transaction approval. They are off by default. Do not decrement financial success because a message bounced.

## Community delivery-evidence adapter
Provider callbacks must reach a dedicated Go endpoint with raw-body signature verification, source/account scope, timestamp/replay checks, size limits and event deduplication. Correlate provider message ID to notification intent. Unmatched callbacks go to quarantine. Test provider API/Novu propagation of metadata and references; a template-only metadata assumption is insufficient. The adapter is required because Community's built-in email activity tracking is not included [S7].

Verify retryable versus permanent failure per selected provider. Backoff with jitter, quotas and circuit breakers must not send expired codes. Suppression is keyed to the normalised mailbox/contact version and category policy. Do not change to another provider merely to bypass a hard bounce/complaint. Ambiguous sends need duplicate-risk review before manual resend. Staff resend requires permission, reason, current guard/recipient check and audit; it must never create a payment or resend an expired challenge.

## APIs to specify with Go implementation
Private: dispatch/eligibility lookup, subscriber synchronisation, provider-delivery callback and suppression lookup. Customer: notification feed/preferences, safe reference view and subscription endpoint. Admin: filtered delivery timeline, dead-letter review, controlled resend, preview, release/sync evidence and sender-health views. The existing Go API remains the security boundary; browsers never receive Novu secret keys or direct workflow-trigger permission.

Document each concrete route and error contract in the shared OpenAPI workspace when implemented. This document deliberately does not pretend an endpoint already exists. Trace IDs, provider IDs and relevant release hashes join support investigations across Go, Novu and email without exposing secrets in public URLs.
